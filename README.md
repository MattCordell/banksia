# banksia

Modular synthetic patient data generator for data analytics and machine learning training. Produces realistic Australian patient cohorts with demographically-weighted populations and condition-specific laboratory results.

## Quick start

```bash
pip install -e .
```

After installation, the `banksia` CLI command is also available:

```bash
banksia --mode single --condition "Hypothyroidism" --sex female --age 54
```

## Usage

The generator supports three modes: **single** (one patient), **cohort** (population + labs), and **population** (demographics only).

### Generate a single patient

```bash
python generate.py --mode single --condition "Hypothyroidism" --sex female --age 54
```

Prints a single patient record with demographics and lab results. Useful for inspecting how a specific condition affects lab values.

### Generate a cohort

```bash
python generate.py --mode cohort --n 200 --output cohort.csv
```

Generates `n` patients with ABS-weighted demographics, assigns random conditions, and produces lab results for each. This is the default mode.

### Generate a cohort with AMT product-level medicines

```bash
python generate.py --mode cohort --n 200 --med-ecl-template amt-tpuu --output cohort.csv
```

Uses the `amt-tpuu` ECL template to resolve prescribed medicines to Trade Product Unit of Use (TPUU) level via Ontoserver, instead of raw ingredient concepts.

### Generate population demographics only

```bash
python generate.py --mode population --n 200 --output population.csv
```

Produces demographic records (age, sex, state, lifestyle, anthropometrics) without lab results.

| Option | Description | Default |

## How it works

### Pipeline overview

```
ABS population data ──► population/ ──► List[PatientContext]
                                              │
                                              ▼
                         laboratory/ ◄── condition profiles (JSON)
                              │
                              ▼
                        Dict per patient (flat lab results)
                              │
                              ▼
                         medicines/ ◄── prescriptions config (JSON)
                              │
                              ▼
                        Dict per patient (lab results + medicines)
                              │
                              ▼
                        formatters/ ──► CSV output
```

1. **Population generation** — Samples demographics from ABS population projections (age, sex, state), weighted by real population counts. Assigns lifestyle factors and generates anthropometrics.
2. **Condition assignment** — Each patient is assigned a condition (or "Healthy") which determines how their lab values deviate from baseline.
3. **Lab generation** — For each patient, lab panels are generated by sampling from statistical distributions. Condition overrides shift means/SDs to produce clinically realistic abnormalities. Demographic adjustments (sex, age, lifestyle) are applied as multipliers.
4. **Medicine assignment** — Based on the patient's condition, medicines are selected from `prescriptions.json`. Substance codes can optionally be expanded to product-level concepts (e.g. AMT TPUU) via Ontoserver ECL queries.
5. **Output** — Results are flattened into a single row per patient and written to CSV.

### PatientContext

The `PatientContext` dataclass (defined in `common/types.py`) bridges modules:

```
Sex, Age, State, Lifestyle[], Height, Weight, Condition
```

The population module produces these; the laboratory module consumes them.

### Adjustment system

Lab values are adjusted by three independent factors that stack multiplicatively:

- **Sex** — e.g. males have higher haemoglobin baselines
- **Age** — slope-based adjustments relative to a reference age (e.g. creatinine increases with age)
- **Lifestyle** — multipliers for `smoker`, `heavy_drinker`, `athlete`, `sedentary`, `high_bmi`

### Calculated fields

Some results are derived rather than sampled directly:

- **eGFR** — 2021 CKD-EPI race-free equation (from creatinine, age, sex)
- **Anion gap** — Na − Cl − HCO₃
- **FBC differential** — Dirichlet sampling maintains realistic proportions across neutrophils, lymphocytes, monocytes, eosinophils, and basophils

### Shared value cache

Tests that appear in multiple panels (e.g. Sodium in both MBAP and Kidney Function) are sampled once and reused, ensuring internal consistency.

## Configuration

Panels and conditions are defined entirely in JSON — no code changes needed to add or modify them.

### Panels (`laboratory/panels.json`)

Defines 12 lab panels with 80+ individual tests:

| Panel | Key tests |
|-------|-----------|
| MBAP | Sodium, Potassium, Chloride, Bicarbonate, Calcium, Phosphate, Urea, Creatinine, eGFR, Glucose, Albumin, Bilirubin, ALP, AST, ALT, GGT, LDH, Cholesterol, and more |
| FBC | WBC, Haemoglobin, Platelets, MCV + differential (Neutrophils, Lymphocytes, Monocytes, Eosinophils, Basophils) |
| LFT | ALT, AST, GGT, ALP, Bilirubin, Albumin |
| Lipid Panel | Total Cholesterol, HDL, LDL, Triglycerides |
| Iron Studies | Ferritin, Serum Iron, Transferrin, Transferrin Saturation |
| Thyroid Panel | TSH, Free T4 |
| Bone Profile | Calcium, Phosphate, ALP |
| B12 & Folate | Vitamin B12, Folate |
| Kidney Function | Sodium, Potassium, Urea, Creatinine, eGFR |
| Immunoglobulins | IgG, IgA, IgM |
| CRP | CRP |

Each test specifies a statistical distribution (`normal`, `lognormal`, `uniform`, or `gamma`), mean, SD, and optional min/max bounds, plus optional sex, age, and lifestyle adjustments.

### Conditions (`laboratory/conditions.json`)

Defines 16 clinical conditions that override baseline lab parameters:

Healthy, Alcoholic Liver Disease, Chronic Liver Disease / Cirrhosis, Type 2 Diabetes Mellitus, Essential Hypertension, Hyperlipidaemia, Ischaemic Heart Disease, Heart Failure (Chronic), Chronic Kidney Disease (Stage 3-4), COPD, NAFLD, Osteoarthritis, Rheumatoid Arthritis, Hypothyroidism, Hyperthyroidism, Iron Deficiency Anaemia

Conditions inherit from the "Healthy" baseline and override specific test parameters (mean, SD, distribution) to produce disease-appropriate abnormalities.

### Adding a new condition

Add an entry to `conditions.json`:

```json
"New Condition": {
  "inherits": "Healthy",
  "panel_overrides": {
    "Panel Name": {
      "Test Name": {
        "mean": 150,
        "sd": 40
      }
    }
  }
}
```

Only the parameters you specify are overridden — everything else inherits from the baseline.

### Adding a new panel

Add a panel entry to `panels.json` with test definitions. Each test needs at minimum a `distribution`, `mean`, and `sd`.

## Population model

Demographics are sampled from ABS Cat. 3235.0 population projections, weighted by actual population counts across state, age group, and sex. This produces cohorts that reflect the real Australian population distribution.

### Lifestyle factors

Assigned probabilistically based on age and sex using rates from the ABS National Health Survey:

| Factor | Notes |
|--------|-------|
| `smoker` | Age ≥ 16; age-specific rates (8–15%); sex-adjusted |
| `heavy_drinker` | Age ≥ 14; age-specific rates (15–36%); sex-adjusted |
| `athlete` | Mutually exclusive with `sedentary` |
| `sedentary` | Mutually exclusive with `athlete`; rates increase with age |
| `high_bmi` | Age-specific rates (10–70%); sex-adjusted |

### Anthropometrics

Height and weight are generated from age- and sex-specific distributions based on Australian adult health statistics, with growth models for paediatric ages and adjustments for elderly patients. The `high_bmi` flag iteratively increases weight until BMI exceeds 30.

## Project structure

| Path | Purpose |
|------|---------|
| `generate.py` | CLI orchestrator — parses args, wires modules together |
| `common/` | Shared utilities — `PatientContext` dataclass, sampling engine, config loading, demographic adjustments |
| `laboratory/` | Lab result generator — panels, conditions, calculated fields (eGFR, anion gap, FBC differential) |
| `population/` | Population generator — ABS-weighted demographics, lifestyle factors, anthropometrics |
| `formatters/` | Output formatting — CSV writer (FHIR planned) |
| `tools/` | Reference files (not part of the generation pipeline) |
| `SNOMED Analysis/` | Scripts for tracking SNOMED CT disease code changes across editions (standalone) |

## Performance

Generation time is **O(unique ECL expressions)**, not O(patients). The dominant cost is the initial set of SNOMED CT ECL expansions against Ontoserver (including any pagination required per query). Once all unique expansions have been cached in memory, the per-patient loop — condition assignment, lab sampling, medicine selection — is purely in-memory and near-instant.

For a given set of conditions and medicine categories on a single edition, the cold-cache warm-up takes roughly 1 minute regardless of cohort size. Generating 100 or 5,000 patients takes approximately the same wall-clock time. Use `--no-snomed` to skip all terminology server calls for fully offline generation.
